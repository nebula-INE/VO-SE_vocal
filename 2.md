# VO-SE Web UI 再設計ロードマップ

## 1. Overview


VO-SE の Desktop 版と Web 版で分離している GUI / UX を整理し、Desktop 版を基準とした共通の操作体系・情報設計へ統一する。

同時に Web 版を単なる「iPad 向け UI」から、Desktop / Tablet / Phone のすべてに対応する Responsive UI へ再設計する。

対象プラットフォーム：

* Desktop
* Web Browser
* iPad / Tablet
* iPhone / Smartphone

基本方針：

> **Desktop を UX の基準とし、Web はその操作体系と情報設計を維持した Responsive Frontend として再構築する。**

ただし、Desktop の画面をそのまま縮小するのではなく、画面サイズ・入力方式・操作密度に応じてレイアウトと情報表示方法を変える。

---

# 2. Goals

## 2.1 GUI / UX の統一

Desktop と Web で以下を可能な限り統一する。

* UI terminology
* Button names
* Icons
* Color / Theme
* Track 操作
* Note 操作
* Lyric 編集
* Pitch 編集
* Timing 編集
* Parameter 編集
* Timeline 操作
* Voice 選択
* Project 操作
* Undo / Redo
* Save / Load
* Render / Export
* 基本的な Keyboard Shortcut

Desktop と Web を別製品として設計するのではなく、

```text
                 VO-SE Core
                     │
             ┌───────┴───────┐
             │               │
          Desktop           Web
             │               │
        Desktop UX     Responsive UX
```

という構造を基本とする。

---

# 3. Non-Goals

以下は避ける。

### 3.1 Desktop UI の単純な Web 移植

Desktop のウィンドウ構造をそのまま HTML/CSS に置き換えることはしない。

### 3.2 iPad UI の単純な縮小

iPad 用 UI をそのまま iPhone の画面に押し込む設計はしない。

### 3.3 Platform ごとの独立 UX

Desktop / iPad / iPhone で操作体系を完全に別々にしない。

共通の編集モデルを維持した上で、表示方法だけを最適化する。

---

# 4. Design Philosophy

## 4.1 Desktop = UX Reference

現在の Desktop 版を、VO-SE の基本的な情報設計・操作モデルを決めるためのリファレンスとする。

ただし、

> Desktop の見た目をそのまま再現する

ことを目的にはしない。

Desktop から以下を抽出する。

* 何を編集できるか
* どの機能が重要か
* 各機能がどこに配置されるか
* 操作の順序
* 操作対象
* 状態表示
* 編集フロー

これらを Web UI の共通仕様として定義する。

# 8. Desktop Layout

Desktop では複数の編集領域を同時表示する。

```text
┌─────────────────────────────────────────────┐
│ Toolbar                                     │
├────────┬──────────────────────────┬─────────┤
│        │                          │         │
│ Track  │                          │Parameter│
│ List   │       Piano Roll         │ /       │
│        │                          │Inspector│
│        │                          │         │
├────────┴──────────────────────────┴─────────┤
│ Timeline                                    │
├─────────────────────────────────────────────┤
│ Transport / Status                          │
└─────────────────────────────────────────────┘
```

特徴：

* Track List 常時表示
* Piano Roll 最大領域
* Inspector / Parameter Panel 常時表示
* Timeline 常時表示
* Transport 常時表示
* Mouse + Keyboard 操作を最大限活用

# 9. iPad / Tablet Layout

iPad では Desktop の編集思想を維持しながら、タッチ操作に最適化する。

```text
┌───────────────────────────────┐
│ Toolbar                       │
├───────────────────┬───────────┤
│                   │           │
│                   │ Parameter │
│    Piano Roll     │ /         │
│                   │ Inspector │
│                   │           │
├───────────────────┴───────────┤
│ Timeline                      │
├───────────────────────────────┤
│ Transport                     │
└───────────────────────────────┘
```

状況によって：

* Track List を Overlay 化
* Inspector を Collapsible Panel 化
* Parameter Panel を Sheet 化
* Toolbar を簡略化

する。

# 10. iPhone / Smartphone Layout

iPhone では「全部を同時表示」することを目的にしない。

重要な編集領域を優先し、Panel を画面遷移 / Bottom Sheet / Overlay として表示する。

基本構造：

```text
┌──────────────────┐
│ Toolbar          │
├──────────────────┤
│                  │
│                  │
│    Piano Roll    │
│                  │
│                  │
├──────────────────┤
│ Timeline         │
├──────────────────┤
│ Transport        │
├──────────────────┤
│ Editor Controls  │
└──────────────────┘
```

必要な情報：

```text
Piano Roll
   ↓
Track
   ↓
Inspector
   ↓
Parameter
```

のように切り替えて表示する。

# 36. Guiding Principle

VO-SE の Responsive UI は、

```text
Desktop UI
    ↓
Responsive Design
```

ではなく、

```text
VO-SE Editing Model
        ↓
Common Design System
        ↓
Common Interaction Model
        ↓
Platform-specific Layout
```

として設計する。

つまり、

**機能は共通化し、情報設計も共通化し、表示方法だけを画面と入力方式に合わせて変える。**

これを Web UI 再設計の基本原則とする。
