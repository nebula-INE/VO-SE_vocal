# WAV書き出しノイズ解消・高音質ピッチ補正 実装計画

## 1. 背景とノイズ発生原因の特定
ユーザーから「WAVファイルの書き出し時に、大きくガサガサ・ザラザラしたノイズが乗る」という報告がありました。
コード検証の結果、以下の5つの複合原因によりノイズが発生していることを特定しました：

1. **グレイン境界の位相不一致（Phase Incoherence）**
   - `psolaPitchShiftBuffer` 内で `analysisMark` と `synthMark` の進み幅の計算に齟齬があり、声帯振動（ピッチパルス）の同位相点ではなく不連続な位置から波形を切り出してオーバーラップ加算していたため、波形の位相干渉による激しいザラつき・バズ音（Comb Filtering）が発生していました。
2. **ウェイト除算によるAM変調（振幅の周期的ガタつき）**
   - 不均等な窓関数の重なりを平滑化ウェイトで割る処理（`out[i] / smoothedWeight[i]`）がピッチ周期ごとに振幅変調（AMリップル）を引き起こし、ブザーのようなガサガサ音を生み出していました。
3. **デクリック処理の誤検知・波形破壊**
   - `declickBuffer` がボーカルの高周波成分やアタックを「スパイク」と誤検知して直線補間で潰してしまい、矩形波状の歪み（ビットクラッシャーのようなノイズ）を付加していました。
4. **過度なEQブーストとリミッター不在によるデジタルクリッピング**
   - `applyClarityCompensation` で高域（3.8kHz, 9kHz）を最大+5.3dB増幅しているにもかかわらず、リミッターやヘッドルーム管理がなかったため、波形が最大振幅（±1.0）を超えて角落ちし、16-bit PCM WAV化の際に強烈な矩形波歪み（音割れ）が発生していました。
5. **ループ境界・無声子音区間でのアルゴリズム不整合**
   - 短い母音ループや子音（s, k, t, sh）の摩擦音・破裂音に対し、無理にグレイン処理を適用したことでざらつきが拡大していました。

## 2. 改善方針とアーキテクチャ

### 対策 1: 位相コヒーレント WSOLA / 厳密同期 PSOLA の再構築
- **相互相関（Cross-Correlation）を用いた波形連続性の担保**:
  単なるピーク検索（`findLocalEpoch`）の代わりに、前後のグレインとの波形連続性を相互相関でマッチングするアルゴリズム（WSOLA原理）を採用。隣接フレーム同士の位相を完全に一致させ、波形の打ち消しや周期境界の段差をゼロにします。
- **完全なパーティション・オブ・ユニティ（Partition of Unity）**:
  Hann窓のオーバーラップ加算が常に数学的にフラット（総和1.0）となるホップサイズ管理を徹底し、不安定な重み除算（AM変調の原因）を完全に撤廃します。

### 対策 2: 高品質リサンプリング＋フォルマント適応フィルタへのシームレス統合
- 音高差が小さい領域（±1半音以内）や無声子音区間では、波形破壊のリスクがあるグレイン分割を行わず、帯域制限補間（Band-limited Cubic / Hermite Resampling）＋アンチエイリアシングフィルタを適用。原音のクリアな質感を100%保持します。
- 音高差が大きい領域では、声質（フォルマント周波数）が狂わないようスペクトルエンベロープを保持しながら滑らかにピッチをシフトします。

### 対策 3: 0dBFSクリッピング防止（スタジオ品質ソフトリミッター＆ピークノーマライズ）
- EQ補正（プレゼンス強調・抜け向上）のゲインを適正化（過大ブーストを抑え、クリーンな質感にチューニング）。
- 書き出し前に高精度なソフトニー・リミッター（Soft-Knee Peak Limiter）およびピーク正規化（-0.3dBFSターゲット）を通すことで、16-bit PCM WAV変換時のデジタル音割れ・クリッピング歪みを物理的に完全に防ぎます。

### 対策 4: WAV書き出しエンジンUIの安定化と選択性の向上
- エクスポート時のエラーハンドリングを強化し、万が一の際もノイズのないクリーンなモードへ自動フォールバック。
- 設定やヘッダーから必要に応じてエンジン方式（フォルマント保持エンジン／高音質クリーンリサンプラー）を簡単に選べるよう整理します。

1. **`src/psolaPitchShift.ts` の抜本的改修**
   - 位相整合型波形マッチング（WSOLA/PSOLA）の実装
   - 誤爆していた `declickBuffer` および不安定なウェイト除算の撤廃
   - 過大EQの適正化および32-bit浮動小数点リミッター／ピークノーマライザーの組み込み

   - ノートごとの音素特性（母音／無声子音／ループ領域）に応じた最適な処理経路の適用
   - トータルマスター出力でのダイナミックレンジ保護
3. **ビルド検証 & 動作確認**
   - TypeScriptコンパイルおよびリンターのパス確認
   - 実際の音声書き出しフローでノイズが消滅し、クリアなボーカルが出力されることを検証
