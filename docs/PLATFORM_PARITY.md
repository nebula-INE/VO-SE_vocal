# Desktop / Web 機能仕様の対応表

この表は「同じプロジェクトデータに対して、同じ編集操作・保存結果・再生結果になる」ことをDesktop/Webの共通受け入れ条件として管理する。

画面の配置や入力方法はOS・画面サイズに合わせてよいが、ノート/トラックの意味、初期値、編集結果、Undo/Redo、保存形式は一致させる。

## 共通ルール

1. **データ仕様を先に定義する。** UI実装ごとに独立した意味や単位を作らない。
2. **歌詞トークナイズは共通契約で検証する。** `specs/lyric_tokenization_cases.json` をWebとDesktopの両テストから読む。
3. **ピッチはUTAU Mode 2の単位を維持する。** PBS/PBW/PBY/PBMを編集しても、UST import/exportで値を失わない。
4. **編集操作はUndo/Redoに記録する。** 一括編集は1操作、ドラッグ編集はジェスチャー単位で扱う。
5. **再生・レンダー・exportの責務を混ぜない。** UIの仕様統一で合成エンジンや既存の単独WAV exportを不用意に変更しない。
6. **機能の追加時に両プラットフォームのテストを更新する。**

## 残りの監査項目

- 音量・パン・Mute/Soloの保存/読み戻し後の一致
- マスターエフェクトとトラックエフェクトの再生・ミックスダウン結果
- ピッチ / Gender / Tension / Breathのオートメーション値域、補間、時間単位
- UST / VSQX / .vose のimport → 編集 → export往復での保持項目
- 選択範囲、複数選択、ショートカット、Undo/Redoの操作差
- Web/WASMとDesktop/nativeで、同一fixtureを使った結果比較

この表の「対応」は画面要素が存在するだけでなく、データ保存・読み戻しと編集結果まで確認できたときに完了扱いにする。
